OpenAMP Workflows with Lopper
=============================

Overview
--------

OpenAMP integration in Lopper extends the ``gen_domain_dts`` assist so that,
whenever the working tree contains OpenAMP-enabled domains, the OpenAMP assist
is invoked automatically. The assist expands ``remoteproc`` and ``rpmsg``
relationships, creates shared-memory carve-outs, and emits companion artefacts
such as ``amd_platform_info.h``. This guide captures the shared Domain YAML
requirements and processing flow that apply to every operating-system
workflow.

Domain YAML Requirements
------------------------

OpenAMP processing is driven by the Domain YAML that is translated into the
system tree. The schema is documented in ``lopper/specification`` (see the
Execution Domains and Domains YAML chapters for details). The YAML must:

- Provide ``definitions`` entries for carve-outs, vrings, and shared memory.
- Declare domains with ``compatible: "openamp,domain-v1"``.
- Describe ``domain-to-domain`` relations containing ``remoteproc`` and
  ``rpmsg`` sections that link the host and remote domains.

The following excerpt illustrates the required structure (based on a sample YAML snippet):

.. code-block:: yaml

   definitions:
     OpenAMP:
       openamp_channel0_access_srams: &openamp_channel0_access_srams
         - dev: psu_r5_0_atcm_global@ffe00000
           flags: 0
         - dev: psu_r5_0_btcm_global@ffe20000
           flags: 0

       rproc0: &rproc0
         - start: 0x09800000
           size: 0x60000
           no-map: 1

       rpu0vdev0vring0: &rpu0vdev0vring0
         - start: 0x09860000
           size: 0x4000
           no-map: 1

   domains:
     openamp_a53_0_cluster:
       compatible:
         - "openamp,domain-v1"
       os,type: linux
       reserved-memory:
         <<+: [ *rpu0vdev0vring0, *rproc0 ]
       domain-to-domain:
         compatible: openamp,domain-to-domain-v1
         remoteproc-relation:
           compatible: openamp,remoteproc-v2
           remote:
             - openamp_r5_0_cluster

.. note::
   Lopper detects OpenAMP relations after the YAML has been translated into the
   working tree. Ensure the command line loads both the Domain YAML and the
   translation LOPs (``lop-xlate-yaml.dts``) before invoking ``gen_domain_dts``.

Processing Flow
---------------

1. Start from the SDT ``system-top.dts`` generated by SDTGen.
2. Load the Domain YAML alongside the YAML translation LOPs so that the
   ``openamp,domain-v1`` nodes and their properties enter the working tree.
3. Invoke ``gen_domain_dts`` for the target processor/OS. When the tree
   contains OpenAMP relations, the OpenAMP assist runs automatically—no extra
   command-line switches are required.

Artefacts and Follow-on Steps
-----------------------------

- ``system-<domain>.dts`` retains nodes mapped to the selected domain and
  includes OpenAMP carve-outs, mailboxes, and ``remoteproc`` metadata.
- Run the OpenAMP assist in header-only mode to produce ``amd_platform_info.h``
  for FreeRTOS or bare-metal firmware. Set ``ESW_MACHINE`` to the RPU target
  (``psv_cortexr5_0`` for Versal Gen 1, ``psu_cortexr5_0`` for ZynqMP) and run:

  .. code-block:: bash

     ESW_MACHINE=psv_cortexr5_0
     lopper -O -f -v --enhanced --permissive \
       -O . ${CONFIG_DTFILE} -- openamp --openamp_header_only \
       --openamp_output_filename=amd_platform_info.h \
       --openamp_remote=${ESW_MACHINE}

- Inspect the generated DTS/headers to confirm ``reserved-memory`` entries,
  mailbox references, and ``remoteproc`` nodes line up with the Domain YAML.
